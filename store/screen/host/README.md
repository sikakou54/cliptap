# 撮影用ホスト

ストア掲載画像で「他のアプリの入力欄に ClipTap のキーボードから入力している」場面を撮るための、
入力欄だけを持つ小さなWebアプリ。シミュレータのホーム画面へ追加してスタンドアロンで開き、
その上に ClipTap の拡張キーボードを出して撮影する。

配信物ではない。`apps/web` とは独立していて cliptap.net へは出ない。

## 絶対に守ること

**実在するサービスの見た目・名称・ロゴ・固有の文言を再現しない。**
Gmail風・X風・LINE風といった作り方はしない。商標にあたるうえ、実物でないものを
実物らしく見せることになり、掲載画像としての誠実さを失う。

ここで必要なのは「Gmailであること」ではなく「メールの作成欄であること」。
02-scenes のリードも `SNSにもメールにも` としか書いておらず、特定のサービス名を出していない。
無印の入力欄で訴求は満たせる。

具体的には次を入れない。

- 他社のロゴ、アイコン、ブランド配色
- 他社のサービス名（本文・タイトル・アイコン名・ファイル名のいずれにも）
- 他社に固有の言い回し（投稿ボタンの独自名称など）

## 使い方

```bash
node store/screen/host/serve.mjs          # 既定 http://localhost:4599
node store/screen/host/serve.mjs --port 5000
```

シミュレータはMacのネットワークをそのまま使うので、`localhost` がそのまま届く
（Info.plist の `NSAllowsLocalNetworking` が true）。

**ClipTapアプリの 設定 > Developer Menu > Capture Host から開く。**
これが唯一の推奨手順。撮影はこの経路でだけ行う。

1. `serve.mjs` を起こす
2. アプリで 設定 > Developer Menu > Capture Host
3. メニューからレイアウトを選ぶ。言語はメニュー右上で切り替える（localStorageに残る）
4. 入力欄をタップ → 地球儀キーで ClipTap キーボードへ切り替え → 定型文を挿入して撮影
5. 抜けるときは状態バーの左端をタップする（透明な閉じる領域を置いてある）

### Safariで開いてはいけない理由

同じURLをSafariで開くと、キーボードの上にフォーム用のアクセサリバー（∧ ∨ 完了）が必ず出る。
ページ側からは消せず、`textarea` を `contenteditable` に変えても出る（実測）。
掲載画像にブラウザの部品が写り込むため使えない。

WebViewなら `hideKeyboardAccessoryView` が WKContentView の `inputAccessoryView` を
差し替えて消してくれる。`app/capture-host.tsx` はそのためだけの画面。
レイアウトの確認だけならSafariでもよいが、撮影には使わない。

### 撮影時の決まりごと

**必ずメニューからレイアウトを選び直すこと。** WebViewは前回のDOMを復元するため、
入力欄の画面から再開すると前回の本文が残ったまま重ねて挿入される。
入力欄から復帰したときは自動でメニューへ戻すようにしてあるが、手順としても守る。

目的の定型文が一覧の下のほうにあるときは、キーボードのカテゴリで絞る。
ただし英語の「Social media」はチップ幅に収まらず「So…edia」と省略されるので、英語面は絞らず「All」から選ぶ。
メールの件名は、プレビュー右上のボタン（タイトルだけを挿入）で入れる。
件名を先に入れてから本文を入れる。逆順にすると本文へフォーカスが残り、タイトルまで本文へ入る。

## レイアウト

| ファイル | 用途 | 対応するキャプチャ |
|---|---|---|
| `compose-mail.html` | 宛先・件名・本文のメール作成欄 | `02-scene-3-mail-<lang>.png` |
| `compose-post.html` | SNSの投稿コンポーザ | `02-scene-2-sns-<lang>.png` |
| `compose-chat.html` | AIアシスタントとの対話 | `02-scene-1-ai-<lang>.png` |

## 撮影時の注意

- シミュレータの外観はダーク、状態バーは他のキャプチャと同じ時刻へ上書きしておく
  （手順は `docs/MARKETING_STRATEGY.md` §4-5）
- 本文に入れるのは開発用シード（`apps/mobile/dummy.json`）の定型文。ホスト側に文章を直接書かない。
  キーボードから挿入した結果を写すことが目的で、直接書くと何も証明しない
