# ClipTap グロース戦略（インストール最大化）

**対象アプリ**: ClipTap（定型文・スニペット管理アプリ / iOS・Android・Web）
**目的**: ストア自然流入・広告流入・SNS/口コミ流入を増やし、インストール数を最大化する
**前提**: 本ドキュメントは ClipTap の実機能・実課金構成・現状ストア掲載文・公式サイト・未実装のグロース機能をリポジトリ調査した上で作成した「実行可能な戦略」である

> **注記**: 本ドキュメントは戦略提案であり、ここで挙げる SDK 導入・機能実装・広告出稿などは未実施です。実装が必要な施策は「要実装」と明示しています。

---

## 1. 全体方針

### ClipTap の勝ち筋（武器）

1. **拡張キーボード（iOS App Extension + Android カスタムIME）** — 最大の差別化。Gmail/Slack/LINE/X/Instagram 等、**他アプリのテキスト欄から直接定型文を挿入できる**。多くの競合は「アプリ内で完結＝コピペが必要」なので、ここが唯一性。
2. **環境管理（プロファイル）× 変数システム** — 「会社A/会社B/副業」で署名や会社名を自動切り替え。半定型文を半自動生成。
3. **ローカルファースト** — SQLite で完全オフライン、外部送信なし。顧客情報・社外秘を扱う層に強い安心訴求。
4. **Web版連携（cliptap.net）** — PCで整理、スマホで使う運用。

### 最優先で塞ぐべき「穴」（=伸びしろ）

調査で判明した、グロースに必要なのに**未実装**の機能。これがそのまま施策になる。

| 穴 | 現状 | 影響 |
|---|---|---|
| 分析計測基盤 | Firebase Analytics / Amplitude **なし**（AdMob・ATT・RevenueCat購入イベントのみ） | **KPIを測れない＝改善が回らない**。最優先。 |
| レビュー依頼導線 | `expo-store-review` **なし** | 評価数が伸びず、ストア順位・CVRに悪影響 |
| オンボーディング | チュートリアル **なし**（初回起動でいきなりホーム） | 最大価値「拡張キーボード」の有効化に到達せず離脱 |
| 紹介・SNSシェア | 招待コード/referral/SNSシェア **なし**（ファイル出力は端末移行用の全件バックアップのみ） | 口コミによる無料流入の仕組みがゼロ |
| 機能制限時の誘導 | モバイルでは上限到達時（Freeのプロファイル3・カスタム変数5・定型文50・ショートカット50・ショートカットの値5）に確認ダイアログからPaywallへ誘導するが（Webはエラー表示のみ）、案内の表示回数やPaywallへの遷移率の計測は **なし** | 上限到達が課金転換にどれだけつながっているか分からず、誘導を改善できない（インストールKPIには直接影響しないが収益に影響） |
| 公式SNSアカウント | Twitterメタタグはあるが**アカウント実体なし** | オーガニック発信チャネルがない |

### 基本サイクル：測る → 直す → 広げる

```
[測る] 計測基盤を入れ、現状KPIを数値で把握
   ↓
[直す] ストア(ASO)とオンボーディングのCVR/アクティベーションを改善
   ↓
[広げる] 改善後に広告(ASA)・SNS・紹介で流入量を増やす
   ↓ (KPIで効果検証して上位に戻る)
```

**順序が重要**：計測なしに広告を回すと「効いたか分からない」状態で予算を溶かす。CVRが低いままに広告を回すと「穴の空いたバケツ」になる。**先に測定とストア改善、その後に流入拡大**。

## 2. インストール数が伸びない原因の仮説

依頼の7観点 + ClipTap固有の仮説。

### ① ストアで見つけられていない（ASO/発見性）
- 英語のタイトルとサブタイトルは `ClipTap: Text Snippet Keyboard` / `Text expander & canned replies` へ改善済み（「snippet keyboard」「text expander」を取り込んだ）。効果の測定は未実施。
- 日英2言語のみ。スペイン語・中国語・韓国語等の大型市場を取りこぼし。

### ② ストアページを見ても魅力が伝わっていない
- **最大の武器「拡張キーボード」がスクショの前方で伝わっているか**が最重要。一覧表示では最初の数枚しか見られないことが多い。（`store/screen/` を刷新し、1枚目をアイキャッチ `00-hero`、2枚目を `01-keyboard` に配置済み。）

### ③ 競合との差別化が弱い（伝え方の問題）
- 機能自体は差別化されている（キーボード×環境管理×ローカル）が、それが「他アプリで使える」という体験価値として一言で伝わっていない。

### ④ 広告のターゲティング/クリエイティブが弱い
- そもそも広告計測の土台（アトリビューション/コンバージョンイベント）が無く、出稿しても最適化できない。

### ⑤ SNS・口コミで広がる仕組みがない
- referral・SNSシェア・公式アカウントがゼロ。バイラルの起点が存在しない。

### ⑥ 初回体験が弱くレビュー/継続に悪影響
- オンボーディング無し → 拡張キーボードを有効化しないまま離脱 → 価値未体験 → 低評価/未レビュー。**ClipTapはキーボード有効化が最大のアクティベーション関門**。

### ⑦ ユーザーの課題・利用シーンが伝わっていない
- ストア説明文ではターゲット3層（ビジネス/SNS/フリーランス）を定義済みで良質。ただしビジュアル（スクショ・動画）で「シーン」を見せきれていない可能性。

## 4. ASO改善案

### 4-1. アプリ名・タイトル

**現状**（正本は `store/store_ja.txt` / `store_en.txt`）
- 日: `ClipTap : 定型文キーボード・テンプレを1タップ`（28/30字。「定型文キーボード」を含む）
- 英: `ClipTap: Text Snippet Keyboard`（30/30字。**上限ぴったりなので1字も足せない**）

**方針**：最大武器の「キーボード」を日英とも名称レベルで訴求済み。これ以上の変更は文字数の上限に当たるため、次は効果測定（4-9）へ進む。

### 4-2. サブタイトル・短い説明（最重要のキーワード枠）

**現状**（正本は `store/store_ja.txt` / `store_en.txt`）
- 日: `どのアプリにも、メール・SNS・AIプロンプトを直接入力`（28/30字）
- 英: `Text expander & canned replies`（30/30字。**上限ぴったり**）

「text expander」「canned replies」を取り込み済み。A/Bテスト候補の用意は 4-9 のとおり未着手。

### 4-3. 検索キーワードの選定方法

ClipTapが取りに行くべき語の仮説：

| 軸 | 日本語 | 英語 |
|---|---|---|
| カテゴリ | 定型文, テンプレート, スニペット, フレーズ登録 | text template, snippet, text expander |
| 機能 | カスタムキーボード, 単語登録, 辞書登録, 変数, 署名 | custom keyboard, text shortcut, auto text, canned response |
| シーン | メールテンプレ, 営業メール, SNS投稿, ハッシュタグ | email template, canned reply, hashtag |

**選定手順**：
1. App Store / Google Play の検索バーで上記語を打ち、**サジェスト（自動補完）**を全て記録 → 実際に検索されている語が分かる。
2. 各語で検索し、上位表示アプリ＝競合を特定。
3. 検索ボリューム × 競合の強さで、勝てそうな中ボリューム語を優先。
4. iOS の `keywords` フィールド（100字）にカンマ区切りで詰める（タイトル/サブタイトルと重複させない）。Google Play はキーワードフィールドが無いため**説明文への自然な織り込み**で対応。

### 4-4. 競合キーワード調査の方法

- **無料**: App Store/Play のサジェスト、関連アプリ欄、競合のレビュー文（ユーザーがどんな言葉で価値を語るか）。
- **ツール（無料枠/低額）**: AppTweak / Sensor Tower / Astro / MobileAction の無料トライアル・無料枠でキーワードランキング・競合の獲得キーワードを抽出。
- 競合の「タイトル/サブタイトルに入れている語」を書き出し、ClipTap が未取得の語を埋める。

### 4-5. スクリーンショット改善案

**現状素材**: `store/screen/` に7枚のHTMLソース。LP（`apps/web/lp/lp.css`）と同一のデザインシステムで組んであり、各スライドにはアプリ画面のキャプチャ（`apps/web/public/image/`）が入る。

キャプチャは**すべてシミュレータ撮影**（1206×2622、ダークモード、開発用シード `apps/mobile/dummy.json` の架空データ、プロファイルは「A社用」／en は「Client A」）で、ファイル名に `-ja` / `-en` を持ち言語別に出し分ける。実機キャプチャは残っていない。

他アプリへの挿入面は**すべて撮影用ホスト**（`store/screen/host/`）で撮る。
`01-hero-right-insert` / `02-scene-*` / `05-shortcuts-right-keyboard` の全部が対象で、
アプリの 設定 > Developer Menu > Capture Host（WebView）から開く。
メール・投稿・メッセージ・AIとの対話・入力フォームという場面に当たるアプリがシミュレータに無く、
あっても他社のUIを掲載画像へ持ち込まないため。
実在するサービスに似せない方針と理由は `store/screen/host/README.md` を正とする。

他アプリへ挿入する面は**すべて「挿入する直前」**で撮る。キーボードのプレビューに
これから入る文字と挿入ボタンが出ている状態で、1枚で「選ぶ → 入る」が伝わる。

| # | ファイル | 訴求 |
|---|---|---|
| 1 | `00-hero.html` | アイキャッチ。LPのヒーロー（`#top`）「いつもの文章を、ワンタップで。」を逐語。見出しのみ他より大きく組む |
| 2 | `01-keyboard.html` | 拡張キーボードで他アプリに挿入（最大価値を前方に） |
| 3 | `02-scenes.html` | 使う場面。投稿欄とメール作成欄へキーボードから挿入 |
| 4 | `03-variables.html` | システム変数7種 × 書式94種 |
| 5 | `04-profiles.html` | カスタム変数とプロファイル切り替え |
| 6 | `05-shortcuts.html` | ショートカット。電話番号や住所などの値だけをキーボードから入力 |
| 7 | `06-pricing.html` | 締めのポスター（濃紺）。数字帯は LP の stats を逐語（50件／1タップ／登録不要／端末内） |

英字ラベル（kicker）、アプリアイコン＋アプリ名のロックアップ、見出しと端末を分ける罫は全面から外してある。面に載るのは見出し・リード・端末・キャプション。

**LP との関係**

掲載画像は LP の同じ節と**同じ主張・同じ語彙**で組む。ただし版面の制約（`.head h1 .line` は
nowrap、ios65 の版面は見出し1行が ja 11字 / 欧文 23字、アイキャッチは ja 9字 / 欧文 20字、
`.stat-label` は35字）で LP の原文がそのまま入らない面があるため、**逐語であることは前提にしない**。
差分が出た面は、その理由をスライド冒頭のコメントに列挙する（`02-scenes.html` と
`06-pricing.html` が実例）。LP を参照するときは**行番号ではなく節のアンカー**
（`#top` / `#scenes` / `#variables` / `#profiles` / `#shortcuts` / `#flow` / `#pricing` / `#cta`）で書く。
行番号で書くと LP の改稿ごとに参照が全滅し、文言のドリフトに気づけなくなる。

**再生成の手順**

```bash
npm run store:screens
```

出力先は `store/out/<canvas>/<lang>/` と `apps/web/public/ogp/`。canvas は `ios65`（1242×2688）と `ipad13`（2064×2752）、言語は ja / en。OGP（1200×630）は `00-hero` から生成され、LP の `og:image` の実体をそのまま置き換える（シェアカードとリンク先ページの第一声が一致する）。
文言を直すときは `store/screen/NN-*.html` を1つ編集すれば ja / en とすべての canvas に同時に反映される。

**端末キャプチャの撮り直し手順**

`.claude/skills/full-test/scripts/` の `sim.sh` / `state.sh` を使う。言語ごとに1巡し、`-ja` / `-en` の両方を揃える（片方だけだと `build.mjs` が止まる）。

1. `state.sh wipe` → `state.sh plan pro` → `state.sh pref set '@dev_ads_disabled' '1'`。Proかつ広告オフにしないとバナーと訴求バナーが写り込む。シードは空のDBにしか入らないため、言語を変えるたびに wipe が要る
2. `sim.sh locale <ja|en>`（端末が再起動する）→ `sim.sh launch`。シードが端末の言語に合う組を投入する
3. `xcrun simctl status_bar <udid> override --time <HH:MM> --batteryState discharging --batteryLevel 100 --wifiBars 3 --cellularBars 4`
   時刻は **9:41 ではなく、システム変数画面に出ている実時刻に合わせる**。`{{time}}` は端末の実時刻で描画されるので、9:41 に固定すると同じ画面の中で状態バーと値が食い違う
4. アプリはプロファイル「A社用」（en は Client A）に切り替えてから撮る
5. キーボード面を撮る。**DBを wipe したあとは必ずシミュレータごと再起動する**。拡張キーボードは消えたDBを掴んだままになり、「No snippets available」と出たまま直らない
   - 撮影用ホストの面は `node store/screen/host/serve.mjs` を起こし、
     **設定 > Developer Menu > Capture Host** から開く（Safariで開くとアクセサリバーが写り込む）。
     **必ずメニューからレイアウトを選び直す**（入力欄の画面はDOMごと復元されるため、前回の本文が残る）
   - 定型文はキーボードのカテゴリで絞ると目的のものが上位に来る。en の「Social media」はチップ幅に収まらず
     「So…edia」と省略されるので、英語面は絞らず「All」から選ぶ
6. 撮ったPNGを `apps/web/public/image/<name>-<lang>.png` へ置き、`build.mjs` → `html_to_png.js` を回す

**残っている改善余地**
- iPad面7枚はiPhoneのフレーム合成で、iPadの画面が1枚も入っていない（`_shared.css` に `.phone` が1種類しか無い）。
- 可能なら1枚目を**App Preview動画**化（キーボードで挿入する3秒の動き）。動きは静止画より伝わる。
- Google Play 用（1080×1920、縦横比9:16が上限）とフィーチャーグラフィック（1024×500）は未対応。`_shared.css` に canvas 定義を1ブロック足せば同じソースから出力できる。

### 4-6. アプリ説明文の改善案

現行 `store/store_ja.txt` / `store/store_en.txt` は既に高品質（ターゲット定義・機能・シーン・プライバシーが網羅）。改善は微調整に留める：
- **冒頭3行に「拡張キーボードで他アプリに直接入力できる」**を必ず置く（多くのユーザーは続きを読まない）。
- Google Play 用は SEO を意識し、狙いキーワードを自然に2〜3回反復。
- 「こんな方におすすめ」は維持（CVRに効く社会的証明的な訴求）。

### 4-7. アイコン改善案

- 現状アイコン（`apps/mobile/assets/icon.png`）の認識性を、競合アイコンと**並べて比較**（ストアの検索結果は小さく表示される）。
- 「タップ」「コピー」「キーボード」を想起させるシンプルなモチーフか検証。
- アイコンA/Bテスト（後述）でCVRを実測してから変更判断。**第一印象で変更しない**。

### 4-8. レビュー評価を高める施策

- **レビュー依頼導線を実装（要実装）**：`expo-store-review` を導入し、**ポジティブ体験の直後**（例: コピー/キーボード挿入が累計N回成功、かつ起動X日目）に控えめに依頼。エラー直後やオンボーディング中は避ける。
- 年に最大3回までというOS制約に合わせ、**満足度の高いタイミングを狙い撃ち**。
- アプリ内で「満足？」→ Yesならストアレビューへ、Noなら要望フォーム（メール）へ、の2段分岐で低評価がストアに流出するのを防ぐ。

### 4-9. ストア掲載情報のA/Bテスト案

- **iOS**: App Store Connect の **Product Page Optimization (PPO)** で、スクショ1枚目・アイコンを最大3バリエーション同時テスト。
- **Android**: Google Play Console の **ストアの掲載情報のテスト**で、アイコン・スクショ・短い説明・フィーチャーグラフィックをA/B。
- テスト優先順位: ①スクショ1枚目 → ②アイコン → ③サブタイトル/短い説明。**一度に1要素**だけ変える。

## 9. 初回体験・オンボーディング改善案

> 現状オンボーディングなし＝**最大価値「拡張キーボード」の有効化に到達せず離脱**している懸念。ここがClipTap最大のアクティベーション関門。

**3画面ウォークスルー案（要実装）**：
1. **価値訴求**：「どのアプリでも、定型文をワンタップ入力」— 最大価値を最初に。
2. **キーボード設定誘導**：iOSは設定アプリでのキーボード追加・フルアクセス許可、Androidは入力方式の有効化を**ステップ画像付きで案内**。ここが離脱多発地点なので最重要。
3. **最初のスニペット作成**：サンプル定型文を1つ用意し、実際に作って→キーボードで挿入する**成功体験**まで誘導。

**各タイミングの設計**：
- **会員登録**：現状任意（ログインなしで全機能可）＝良い設計。**初回は登録を求めない**。価値体験後、Web連携/Pro共有の文脈で任意提示。
- **プッシュ通知許可（通知を導入する場合・要実装）**：初回起動では**求めない**。価値体験後、または「更新通知を受け取る？」の文脈で。
- **ATT（iOS）**：既存実装あり。オンボーディング後、最初のホーム表示時など落ち着いたタイミングで。
- **最初の成功体験**：「サンプル定型文をキーボードで他アプリに挿入できた」を1分以内に到達させる。
- **離脱ポイント分析（要計測基盤）**：オンボーディング各ステップ・キーボード有効化・初回コピーをイベント計測し、どこで落ちるかをファネルで可視化。

## 12. 広告予算を使う施策

- **最初に使うべき媒体**：Apple Search Ads（顕在ニーズ・低CPI・少額可・計測容易）。次点で Google UAC（Android量）。

- **成果拡大の方法**：勝ち媒体・勝ちキーワード・勝ちクリエイティブに予算を段階的に増額（一気に倍々にせず20〜30%ずつ）。勝ち素材の派生を作って横展開。

## 13. KPI一覧

> **前提**：太字の指標の多くは現状**計測できない**。まず計測基盤（Firebase Analytics + App Store Connect + Play Console + RevenueCat + ASA/広告管理画面）の整備が必須。

| KPI | 定義 | 目安/方向 | 取得方法 |
|---|---|---|---|
| ストア表示回数（インプレッション） | 検索/閲覧でストアに表示された数 | 増やす | App Store Connect / Play Console |
| ストアページ閲覧数 | プロダクトページ閲覧数 | 増やす | 同上 |
| インストール率（CVR） | 閲覧→インストール率 | iOS 30%前後を一つの目安に改善 | 同上 |
| CPI | インストール単価 | 下げる（ASA低CPIを基準に） | ASA/広告管理画面 |
| 広告クリック率（CTR/TTR） | 表示→クリック率 | 上げる | 各広告媒体 |
| 広告コンバージョン率（CR） | クリック→インストール率 | 上げる | 各広告媒体 |
| **初回起動率** | インストール→起動率 | 高く保つ | **要: Firebase Analytics** |
| **会員登録率** | 起動→登録率（任意なので参考値） | 任意設計のため過度に追わない | **要: Analytics** |
| **キーボード有効化率**（ClipTap固有・重要） | 起動→拡張キーボード有効化率 | **アクティベーションの核。最重要** | **要: Analytics** |
| **1日後継続率（D1）** | 翌日も起動した割合 | 上げる | **要: Analytics** |
| **7日後継続率（D7）** | 7日後も起動した割合 | 上げる | **要: Analytics** |
| レビュー数 | ストアレビュー件数 | 増やす（依頼導線で） | App Store Connect / Play Console |
| 平均評価 | ストア★平均 | 4.5+を目標 | 同上 |
| **紹介経由インストール数** | referral経由DL | 仕組み実装後に計測 | **要: 招待コード機能+Analytics** |

**ClipTap独自の最重要KPI**：**キーボード有効化率**（＝最大価値の体験率）と **D1/D7継続率**。インストール数の先にある「価値到達」を測る。

## 15. 追加で確認すべきデータ

戦略の精度を上げるため、以下の実数値・前提を確認したい：

1. **現状KPIの実数値** — 月間DL数、現在の平均評価・レビュー数、CVR、D1/D7継続率、Pro転換率（現状ほぼ未計測のはず）。
2. **計測基盤の有無確認** — Firebase Analytics 等が本当に未導入か、導入予定はあるか。**最優先で埋めるべきギャップ**。
3. **広告予算の上限** — 月いくらまで広告に使えるか（少額前提か）。
4. **ローカライズ優先言語** — 日英以外で狙う市場（中/韓/西/独 等）の希望。
5. **競合の特定** — ClipTapが「これに勝ちたい」と思う具体的な競合アプリ名（あれば調査を集中できる）。
6. **メインターゲットの優先順位** — 営業/CS・フリーランス・SNS運用者のうち、最初に集中突破したい層。
7. **実装可能な工数** — レビュー依頼/オンボーディング/紹介機能などの「要実装」施策にどれだけ着手できるか。
8. **公式チャネルの方針** — X以外にどのSNSを運用するか、発信の主担当を置けるか。
