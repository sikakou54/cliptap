# リリース前 全画面チェック

シミュレータを実際に操作して確認する。型チェックとlintが通っただけでは
アニメーション・アセット解決・プルリフレッシュ・ピッカーの初期値は検証できない
（`apps/mobile` にはテストが1件も無い）。

## 進め方

### ステップ1: 静的チェック

```bash
.claude/skills/release-check/scripts/preflight.sh
```

型チェック・テスト・mobile lint・Androidビルド・Web版スターターファイルの整合を見る。
**1件でも失敗したらここで止める。** 画面確認へ進まない。

`quick` を渡すとAndroidビルドを省略できる（コード修正の反復中のみ）。

### ステップ1.5: 公開文書の棚卸し

`preflight.sh` の `npm test` は `packages/shared/tests/publicDocs/claims.ts` に登録済みの主張だけを見る。
**未登録の主張は誰も見ていない**ので、リリースごとにここで棚卸しする。

```bash
git diff --name-only origin/release/prod..HEAD
```

1. 変更されたファイルを `claims.ts` の各主張の `evidence` と突き合わせ、交差したものは
   その主張の `sites` を全部読み直す
2. 同じ期間に公開文書（`store/`、`apps/web/index.html`、`apps/web/en/index.html`、
   `apps/web/public/*.html`、`packages/shared/src/i18n/*.json`）へ足した文のうち、
   台帳に無い事実の主張を `claims.ts` へ登録する
3. 読む観点は4つ。過去に壊れたのはすべてこの4種だった
   — **挙動**（何が起きるか）／**条件**（いつ起きるか、解除の条件を書き落としていないか）／
   **手数**（タップ数を謳っているなら実機で数える）／**列挙**（「〜のみ」が実装と一致しているか）

**手数の主張は実機でしか確かめられない。** 拡張キーボードからの挿入は一覧の行をタップして
詳細を開き、下部の挿入ボタンを押す2タップである。ステップ3の巡回で実際に数える。

### ステップ2: シミュレータの準備

```bash
S=.claude/skills/release-check/scripts/sim.sh
$S boot            # 起動中のシミュレータを確認（無ければ起動）
$S install         # アプリをビルドしてインストール（数分かかる）
$S geometry        # 座標変換の倍率を確認
```

`install` は `npm run ios` を呼ぶ。差分が無ければ2回目以降は `$S launch` だけでよい。

**アクセシビリティ権限が必要**。未許可なら `sim.sh` が明示的にエラーを出す。
システム設定 > プライバシーとセキュリティ > アクセシビリティ で、このセッションの
親アプリ（VS Code など）を許可する。付与直後は再起動なしで有効になることが多い。

### ステップ3: 全画面の巡回

`reference/screens.md` を開き、**上から順に**すべての項目を消化する。
各画面で次を繰り返す。

```bash
$S launch                    # クリーンな状態から開始
$S shot home                 # 現在の画面を撮る
# → 出力されたパスを Read で開いて、次にタップする対象の座標を読む
$S tap 105 201               # デバイス座標(ポイント)でタップ
$S shot after-title-tap      # 結果を撮って Read で確認
```

座標はスクリーンショットのピクセルではなく**デバイスのポイント座標**で指定する。
`point = screenshot_pixel / scale`（`$S geometry` が倍率を表示する。iPhoneは通常3）。

使えるコマンド:

| コマンド | 用途 |
|---|---|
| `$S tap <x> <y> [holdMs]` | タップ。`holdMs` を500以上にすると長押し |
| `$S drag <x1> <y1> <x2> <y2> [ms]` | スクロール、プルリフレッシュ、スワイプで閉じる |
| `$S type <text>` | フォーカス中の入力欄へ文字入力 |
| `$S clipboard` | **コピー結果の実値を検証する**。目視より確実 |
| `$S shot <name>` | スクリーンショット。パスを返すので Read で開く |
| `$S logs [分]` | JSレベルのエラー（RedBox / Invariant など）を抽出 |

### ステップ4: 報告

`reference/screens.md` の項目ごとに **OK / NG / 未確認** の3値で記録する。
到達できなかった画面を暗黙にOK扱いしない。NGは「操作 → 期待 → 実際」の形で書く。

最後に `$S logs 30` を実行し、巡回中にJSエラーが出ていないかを確認する。

実機が必要な項目（拡張キーボード、触覚フィードバック、実購入、Android実機）は
`reference/screens.md` の第8節をそのまま手動チェックリストとして残す。

## 操作上の注意

- **連続タップを避ける**。間隔が短いとReact DevToolsのインスペクタが起動して画面を覆う。
  各タップの後に2秒程度あけ、状態がおかしくなったら `$S launch` でやり直す。
- **ディープリンクは使えない**。`simctl openurl` はiOSの「"ClipTap"で開きますか?」ダイアログに
  阻まれる。画面遷移は必ずタップで行う。
- **破壊的な操作の順序**に注意する。削除の確認は最後に回すか、確認後にインポートで復元する。
- 変更のたびに `$S install` は不要。JSのみの変更ならMetroが反映するので `$S launch` で足りる。
  ネイティブ（`ios/`, `android/`, 新規ネイティブ依存）を触った場合のみ再インストールする。

## 特に退行しやすい箇所

過去に実際に壊れた、または壊れかけた箇所。最初に確認する価値が高い。

1. **編集画面が空で開く** — 既存値の読み込み経路
2. **アセットが表示されない** — スプラッシュのアイコン、利用規約・プライバシーポリシーのHTML。
   型チェックでは絶対に検出できず、実行時に静かに壊れる
3. **プルリフレッシュのインジケータが戻らない** — iOS/Androidで実装が別。両方で確認する
4. **開いた直後の選択状態** — 検索画面の環境チップ、変数画面の環境チップ
5. **カテゴリ選択が勝手に外れる** — 画面遷移して戻ったときに維持されるか
6. **ピッカーのキャンセル** — 破棄されず前回の編集が残っていないか
7. **エクスポートのファイルが空** — 共有シートのサイズ表示と、生成ファイルの先頭が
   `{"s":<スキーマ版>,...}` であること
8. **表示とコピーの食い違い** — 変数の値を空のまま保存した環境で、
   一覧に見えている文字列と `$S clipboard` の値が一致すること
9. **掲載文が謳う手数と実際の手数** — 「1タップで挿入」と書いてあっても、
   キーボードからの挿入は行タップ→挿入ボタンの2タップ。実機で数えて確かめる

## 仕様の正本

判断に迷ったら [docs/機能仕様書.md](../../../docs/機能仕様書.md) を正とする。
実装と仕様書が食い違っていた場合は、機能仕様書§1.1に従いソースコードと設定を正とし、仕様書側を現行実装へ合わせる。どちらが正しいか判断できない差はユーザーへ確認する。
